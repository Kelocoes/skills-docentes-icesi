# Skill: `implement-slides`

This skill takes an approved slide specification plan generated by `planning-slides` and builds the presentation HTML file using the **Reveal.js + dist/main.css + dist/main.js** component system of Universidad Icesi, automatically exporting the final **PDF slide deck** (`slides/<topic>/<topic>.pdf`).

---

## Mandatory Reference Inspection

Before implementing the HTML slide deck, the agent **MUST** inspect the core reference manuals and auxiliary skills using `view_file`:
- `skills/slides-generator/references/formatting_rules.md`: Strict CSS pixel bounds (1280x720), typography hierarchy, card constraints, and safe margin rules.
- `skills/slides-generator/references/memory.md`: Component layout catalog, historical fixes, contrast fixes, and `.items-evenly` / `.icon-card` patterns.
- `skills/slides-generator/references/skills/slides-iconification/SKILL.md`: Pure SVG icon system (strictly no emojis allowed).
- `skills/slides-generator/references/skills/slides-svg-graphics/SKILL.md`: Custom raw SVG vector infographics and visual sidebar panels.
- `skills/slides-generator/references/skills/slides-mermaid-diagrams/SKILL.md`: Inline Mermaid specs and mandatory white-card contrast rules for dark slide backgrounds.

---

## Parameters & Usage

- **`spec_file_path`**: Path to the approved specification markdown file saved under `output-skills/slides-generator/[MM-DD-YYYY]_[counter]/spec/<topic>-plan.md`.

Example usage:
```bash
/implement-slides output-skills/slides-generator/07-23-2026_01/spec/react-plan.md
```

### 1. Read & Validate Specification with Pre-Implementation Critique

Before writing any HTML, the agent MUST verify that the specification plan is approved by the user and perform an **agentic critique pass**:

#### Pre-Implementation Checklist:
| Check | Action if FAIL |
|---|---|
| **No external redirects** | Spec contains "Taller Práctico", "Lab 01", "Workshop", "Hands-on Exercise" → **Replace** with self-contained conceptual or deep-dive slides on the same topic. |
| **Self-contained content** | Slide lacks educational payload → **Expand** with detailed explanations, code snippets, or architectural diagrams. |
| **Function signature match** | Check parameter counts against catalog (Section 3A) → **Correct** signature call. |
| **No emojis in icon slots** | Spec contains emoji ([*], ⚙️, , etc.) → **Replace** with inline SVG or custom vector asset (`slides-iconification`). |
| **Code blocks in grids** | Spec attempts to put `<pre><code>` inside `.icon-grid-2` → **Use `icesi.slideTwoCols(...)`** with `.icon-card` containers for strict 50/50 vertical column flow. |
| **Graphic strategy choice** | **Mermaid diagrams fail in PDF exports via Decktape (they render as white boxes).** → **Replace** all Mermaid diagram specs with **custom inline SVG graphics (`slides-svg-graphics`)**. |

### 2. File & Directory Setup

1. Target execution directory: `TARGET_DIR` = `output-skills/slides-generator/[MM-DD-YYYY]_[counter]/`.
2. Slides destination directory: `<TARGET_DIR>/slides/<topic>/`.
3. Copy bundled dependencies and resources: Ensure `dist/main.js` and `dist/main.css` are copied into `<TARGET_DIR>/dist/`, and copy `resources/` (fonts and logos) into `<TARGET_DIR>/resources/`.
4. Code blocks styling: Ensure all `<pre><code>` code blocks use a dark theme background (`#1e1e2e` / `#1a1a2e`) with explicit white/light text and `min-width: 0` / `width: 100%; box-sizing: border-box` inside grid columns (`.col`) to prevent horizontal overflow or overlapping between columns.
5. Create all custom SVGs, icons (`slides-iconification`), and vector graphics (`slides-svg-graphics`) as inline SVG markup inside the slide HTML.

### 3. HTML Slide Generation Rules

#### A. Direct Scripting / Single Tool Call Rule (Token Optimization)
- **NEVER pass inline multi-line HTML strings via shell commands** (e.g. `powershell -Command "..."` or `node -e "..."`). This causes Windows string-escaping errors and bloats context history.
- Write the HTML file `<TARGET_DIR>/slides/<topic>/<topic>.html` directly using a single python build script (`python create_presentation.py`) or `write_to_file`.
- **REVEAL.JS CDN MANDATE**: Always include the official Reveal.js CDN in the `<head>` and `<body>` of the HTML template to ensure Decktape recognizes and compiles the presentation immediately:
  ```html
  <link rel="stylesheet" href="https://cdnjs.cloudflare.com/ajax/libs/reveal.js/5.1.0/reveal.min.css">
  <script src="https://cdnjs.cloudflare.com/ajax/libs/reveal.js/5.1.0/reveal.min.js"></script>
  ```

#### A. Component Catalog Signatures (Mandatory)
Use ONLY functions from `dist/main.js`. Verify argument count matches exactly:

| Function | Args | Usage Notes |
|---|---|---|
| `icesi.titleSlideA(title, subtitle)` | 2 | Main cover slide. Subtitle yellow box accepts `<span class="slide-footer-tag">` for faculty labels. |
| `icesi.titleSlideF(title, subtitle)` | 2 | Visual break for major module shifts (never for external workshop redirects). |
| `icesi.slideStandard(title, content)` | 2 | Single content area slide. |
| `icesi.slideTwoCols(title, col1, col2)` | 3 | Two column split layout. |
| `icesi.slideThreeCols(title, col1, col2, col3)` | 4 | Three column split layout. |
| `icesi.slideFourCards(title, c1t, c1b, c2t, c2b, c3t, c3b, c4t, c4b)` | 9 | 4-card grid. Card headers (`c1t`) are small 14px uppercase labels. |
| `icesi.slideSidebarLeftBlue(title, content, sidebarVisual)` | 3 | Left blue sidebar. `sidebarVisual` accepts SVG graphics, icons, or Mermaid. |
| `icesi.slideSidebarLeftOrange(title, content, sidebarVisual)` | 3 | Left orange sidebar. |
| `icesi.slideSidebarLeftPurple(title, content, sidebarVisual)` | 3 | Left purple sidebar. |
| `icesi.slideStripeTopLeft(title, content)` | 2 | Top left accent banner slide. |
| `icesi.slideStripeTopRight(title, content)` | 2 | Top right accent banner slide. |
| `icesi.sectionSlideA(title)` | **1** | Standard section divider (bottom blue block). |
| `icesi.sectionSlideC(title)` | **1** | Major chapter divider. |
| `icesi.sectionSlideE(title, content)` | **2** | Minimal white divider. Title supports `<br><small style="font-size:0.5em;">`. Optional content for diagrams. |
| `icesi.sectionSlideEBlue(title, content)` | **2** | Blue section divider. Optional content for diagrams. |
| `icesi.sectionSlideEGreen(title, content)` | **2** | Green section divider. Optional content for diagrams. |
| `icesi.sectionSlideEYellow(title, content)` | **2** | Yellow section divider. Optional content for diagrams. |
| `icesi.sectionSlideEOrange(title, content)` | **2** | Orange section divider. Optional content for diagrams. |

#### B. Absolute Prohibition of Emojis & Inline SVG Dimensions
- **NEVER use emoji characters** anywhere in slides.
- Use compact semantic inline SVGs inside `.icon-symbol`, card headers, and sidebar lists.
- **SVG Dimension Rule**: ANY inline `<svg>` code generated by you MUST include explicit `width` and `height` attributes (e.g. `width="400px" height="280px"`) to prevent CSS layout collapse.

#### C. Code Blocks, Highlight.js Theme & Clean Code Mandate
- **Highlight.js Theme Stylesheet Inclusion**: Always include a high-contrast dark theme stylesheet in the `<head>` of the presentation HTML:
  ```html
  <link rel="stylesheet" href="https://cdnjs.cloudflare.com/ajax/libs/highlight.js/11.9.0/styles/atom-one-dark.min.css">
  ```
- **Vivid CSS Token Styles**: Always configure `.hljs-*` color rules in `<style>` so that RevealHighlight colors every syntax token clearly:
  - Annotations / Meta (`.hljs-meta`): `#79c0ff` (cyan/blue).
  - Keywords (`.hljs-keyword`): `#ff7b72` (coral/red).
  - Classes and Types (`.hljs-type`, `.hljs-title.class_`): `#ffa657` (amber/orange).
  - Functions and Methods (`.hljs-title.function_`): `#d2a8ff` (lavender).
  - Strings (`.hljs-string`): `#7ee787` (emerald green).
  - Numbers and Booleans (`.hljs-number`, `.hljs-literal`): `#f2cc60` (gold).
  - Comments (`.hljs-comment`): `#8b949e` (italic grey).
  - HTML/XML tags (`.hljs-tag`, `.hljs-name`): `#7ee787` (green).
  - HTML and Thymeleaf attributes (`.hljs-attr`): `#f472b6` (magenta/pink).
  - Configuration properties (`.hljs-attribute`): `#ffa657` (orange).
- **Clean Code Rule (No Manual HTML Spans)**: NEVER insert manual `<span class="...">` inside `<pre><code>`! RevealHighlight intercepts code blocks and automatically escapes raw HTML tags into literal `&lt;span&gt;` entities on screen. Provide clean code and specify the proper language class (`language-java`, `language-xml`, `language-html`, `language-properties`).

#### D. JavaScript Template Literal Escaping Mandate (`\${...}`)
- Because slides are defined inside JavaScript template literals (backtick strings), any templating or shell syntax matching `${...}` (e.g. Thymeleaf `${user.name}`, JSP EL, or Bash `$VAR`) will be evaluated by JavaScript as variable interpolation at runtime, causing a fatal `ReferenceError`.
- **Mandatory Escape Rule**: You MUST escape all `${...}` occurrences as `\${...}` inside template literal strings.

#### E. 4-Item Density & Horizontal Card Pattern
- The default `.icon-card` is vertical (`flex-direction: column`) and occupies ~110px. When a slide or sidebar contains 4 items, stacking them vertically will overflow the 720px viewport.
- **Horizontal Row Rule**: For 4 items in a list or sidebar layout, format items as horizontal flex cards:
  ```html
  <div style="display:flex; flex-direction:row; align-items:center; gap:12px; background:#ffffff; border:1px solid #CECFD4; border-left:4px solid var(--icesi-blue); border-radius:8px; padding:6px 12px; margin-bottom:8px; box-shadow:0 2px 6px rgba(0,0,0,0.03);">
    <div style="flex-shrink:0; width:34px; height:34px; display:flex; align-items:center; justify-content:center; background:rgba(84,84,233,0.1); border-radius:6px;">
      <!-- SVG icon -->
    </div>
    <div style="flex:1; min-width:0;">
      <div style="font-size:13.5px; font-weight:700; color:#1e293b; line-height:16px;">Title to right of icon</div>
      <div style="font-size:12px; color:#475569; line-height:15px;">Short concise description.</div>
    </div>
  </div>
  ```
- **Sidebar Slide Title Length**: Titles on sidebar slides (`slideSidebarLeft*`) must fit on a single line (maximum 32 characters) to prevent multi-line collision with subheaders (`<h3>`). Avoid negative top margins (`margin-top: -50px`) on content containers when subtitles are present.

#### F. Token-Efficient Visual QA Guidelines (Playwright MCP)
To prevent massive token consumption during visual verification:
1. **Console Verification First**: Check console logs for errors before taking screenshots. If errors exist, fix them in code first without taking redundant screenshots.
2. **Selective Visual Checks**: Do NOT screenshot all slides. Capture only slides that contain complex diagrams, dense 4-card layouts, or modified code blocks.
3. **Cache-Busting URL Mandate**: Always append a version query parameter (`?v=<timestamp>`) when navigating with Playwright (`browser_navigate`) to avoid inspecting stale cached responses.

> **CRITICAL RULE - PREVENT NAVIGATION TIMEOUTS**:
> Direct execution of Decktape over `file://` URIs causes Chromium navigation timeouts on Windows/PowerShell when loading fonts and module scripts.
> You MUST serve the output directory over a local HTTP server before executing Decktape.

#### Step 4.1: Start Local Server
Start local HTTP server in background:
```powershell
npx -y http-server . -p 8080 -s
```

#### Step 4.2: Export PDF Deck via Decktape
Export the presentation HTML to the PDF deliverable (`<TARGET_DIR>/slides/<topic>/<topic>.pdf`) over local HTTP:
```powershell
npx -y decktape reveal --load-pause 2000 "http://localhost:8080/<TARGET_DIR>/slides/<topic>/<topic>.html" "<TARGET_DIR>/slides/<topic>/<topic>.pdf" --size 1280x720
```

#### Step 4.3: Terminate Local Server & Output Directory Hygiene
- Terminate the background `http-server` process after Decktape completes.
- **Output Hygiene**: Ensure that `<TARGET_DIR>` contains ONLY:
  - `spec/<topic>-plan.md`
  - `slides/<topic>/<topic>.html`
  - `slides/<topic>/<topic>.pdf`
  - `dist/main.js` and `dist/main.css`
  - `INFO.md`
- Remove any temporary scratch files or unused assets.
